## Outcome

[PR #3417](https://github.com/huggingface/peft/pull/3417) improved the IA³ documentation with practical usage guidance, target-module selection advice, and a comparison with LoRA. The contribution moved through a changes-requested review to maintainer approval.

## Problem

PEFT's IA³ reference explained the configuration surface but gave users less decision support than the mature LoRA documentation. A reader still had to determine when IA³ was appropriate, what layers should be targeted, and how to verify the trainable-parameter footprint.

## First draft and review

The initial draft added a recommendation banner, a complete fine-tuning example, module-selection guidance, and an IA³-versus-LoRA table. Maintainer `BenjaminBossan` liked the direction but requested changes because parts were redundant and the example did not work as written.

That feedback changed the task from simply adding more prose to ensuring that the documentation was executable, non-duplicative, and consistent with PEFT's existing reference style. The revised version removed redundancy and corrected the example rather than defending the first draft.

## Final contribution

The merged page gives users a compact path from choosing IA³ to configuring target modules and understanding its tradeoffs relative to LoRA. The final scope remained one documentation file, demonstrating that useful developer education can be delivered without expanding the public API.

## What I learned

Documentation examples are code and should be treated with the same correctness standard as tests. More detail is not automatically better: mature documentation benefits from information architecture, accurate examples, and explicit decision guidance. A changes-requested review improved both technical correctness and editorial focus.
